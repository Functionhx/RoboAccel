# 06 · 失败假设档案（failed hypothesis archive）

本项目提出过三个"机理解释"（mechanism explanation）。
**三个都符合当时手上的全部证据，其中两个被实验推翻，一个被大幅收窄。**

保留它们不是为了自责，而是因为：**一个能解释现有数据的假设，
不等于一个正确的假设**。这三次的共同点是——推翻它们的都是
一个**能分离变量的实验**，而不是更多的观察。

---

## 假设 1：latent 是 W8A8 崩溃的瓶颈

**当时的论据（全部为真）** **[已验证]**
* `enc2` 浪费了 16 bit 权重里的 3.4 bit：`|w|max = 0.1831`，而 frac 被
  `MAX_WEIGHT_FRAC = 14` 限制住。
* `p99.9/max = 0.912` → 张量是**整体偏小**，不是离群点主导。
* INT8 下 latent 在 ±1σ 内只有约 6 个量化台阶。
* latent 就是**速度估计**（velocity estimate），经过一个**不能 requantize
  的 CONCAT** 直接进入 actor。
* 速度估计 RMSE 随精度单调恶化：0.036 → 0.034 → 0.044 → 0.126 → 0.560。

这是一条很漂亮的因果链。**它是错的。**

**推翻它的实验** `scripts/layer_sensitivity.py`：逐层单独量化，测动作误差。

| 层 | 单独量化 | 占比 | 去掉这层 | 相对 ALL 的下降 |
|---|---|---|---|---|
| act0 | 0.34666 | **53.2%** | 0.57564 | 11.6% |
| enc2 | 0.08593 | **13.2%** | 0.60052 | 7.8% |
| obs | 0.17027 | 26.1% | 0.65136 | **0.0%** |

`enc2` 只占 13.2%，主导的是 actor 的宽隐藏层。事后看很显然：
**`enc2` 只输出 3 个值进入 28 维 concat，扰动被稀释；
`act0` 扰动 128 个通道，且下游全部受影响。**

**更进一步：任何单层解释都不成立。** 两种归因互相矛盾——
`act0` 单独最差但去掉只恢复 11.6%；`obs` 单独占 26.1% 但去掉**恢复 0.0%**
（下游量化会重新制造同样的误差）；去掉 `enc1` 反而更差（−1.4%）。
单层占比之和 = 222%，所以那是**排序**，不是**分解**。

**存活下来的说法（更弱、更有用）**
> 损伤分布在 actor 的多个隐藏层上且强烈交互，没有任何单层修复有效——
> 去掉任意一层的量化仍保留 ≥82% 的损伤。这也正是**逐层标定
> （per-layer calibration）打不过在环训练**的原因：标定孤立地优化每一层的
> 网格，而交互结构恰好击败这种做法。

英文表述：*The W8A8 collapse is distributed across the actor's hidden layers
with strong error interaction; no per-layer fix addresses it.*

## 假设 2：崩溃是饱和（saturation）造成的

**推翻它的测量** 在标定后的 frac 下直接测每层裁剪比例：

| 层 | frac | grid ± | FP32+ 峰值 / 裁剪率 | QAT 峰值 / 裁剪率 |
|---|---|---|---|---|
| enc0 | 1 | 63.50 | 29.32 / **0.00%** | 33.52 / **0.00%** |
| enc1 | 1 | 63.50 | 37.02 / 0.00% | 61.98 / 0.00% |
| enc2 | 3 | 15.88 | 2.18 / 0.00% | 1.52 / 0.00% |

**什么都没裁剪。** 于是有两个推论：

1. W8A8 的崩溃是**纯粹的分辨率与舍入噪声**，不是饱和 → **加宽网格无效**。
2. activation frac 是 QAT 的**固定输入**，训练改不了它。所以 QAT
   不可能是"把激活缩放进量程"——它们本来就在量程内。
   排除法之后，QAT 能做的只有：**学一组对这些固定网格产生的舍入噪声
   不敏感的权重。**

> 注意：得出这个结论前，`quant_diagnostics.py` 曾报告 80–96% 饱和。
> 那是 [05](05_debugging_history.md) §1.1 的 bug。**差点据此写下错误结论。**

## 假设 3：requantizer 的舍入偏置导致转向失败

**当时的论据（全部为真）** **[已验证]**
* §20 测得每动作偏置在两个轮子上**不对称**：`l_wheel` −6.32 LSB
  vs `r_wheel` −0.19 LSB，折合 **3.84 rad/s 的差速**。
* 持续的差速轮指令 = **持续的偏航力矩（yaw torque）**。
* 预测：yaw 应该比前向跟踪坏得更多。实测 forward 退化 8.4×，
  yaw 退化 **17.6×**，正好是两倍。
* QAT 在有偏算术上训练，两个转向方向**同时**归零，符合"过拟合了一个
  不泛化的 yaw 补偿"。

三条独立观测都吻合。**仍然是错的。**

**推翻它的实验** 加入 `IDEAL_ROUNDING` 开关（`hwq/torch_hw.py`），
用**精确 round-half-away-from-zero** 重训 QAT 2000 步，其余全部不变。

| segment | QAT (硬件舍入) | QAT (理想舍入) |
|---|---|---|
| forward | 1.000 | 1.000 |
| reverse | 0.570 | **0.992** |
| stop | 0.938 | **1.000** |
| **turn_left** | 0.000 | **0.000** |
| **turn_right** | 0.000 | **0.000** |

**转向一点没动。**

**但这不是零结果**：修正舍入让 `reverse` 从 0.570 → 0.992、
`stop` 0.938 → 1.000，各段 yaw RMSE 降约 20%。
**这个偏置是真实的、值得在 RTL 里修的——只是它不是转向失败的原因。**

**接替它的解释（当前最优，仍在检验中）** **[假设]**
即使在理想舍入下，QAT 在转向段的 yaw RMSE（0.193/0.229）仍远差于
PTQ（0.147/0.144），而 QAT 的 forward success 是 1.000 对 PTQ 的 0.000。
**QAT 不是普遍更好或更差，它是在用 yaw 精度换 forward 精度。**

奖励里 `tracking_lin_vel = 2.0` 对 `tracking_ang_vel = 1.0`——
**线速度权重是偏航的两倍**。所以 QAT 把稀缺的 INT8 容量花在
奖励主导的那个轴上，饿死了 yaw。这解释了为什么 **4× 训练预算**
和**修正舍入**都不起作用：两者都没有改变**目标函数**。

**判决性实验已完成 —— 假设 4 被证伪，而且两个预设分支都不对。**

`--reward-ang-vel 2.0 / 4.0` 重训 QAT（同 seed、同 task、同 init、同 2000 步，
带构造后读回断言，确认覆盖真正生效）：

| 运行 | ang_vel 奖励贡献 | `yaw_rmse_rad_s` |
|---|---|---|
| FP32 对照 | 0.00986 | **0.0584** |
| W8A8 ×1 | 0.00913 | 0.1546 |
| W8A8 ×2 | 0.01826（**恰好 2.00×**） | 0.1533 |
| W8A8 ×4 | 0.03646（**恰好 4.00×**） | 0.1540 |

**奖励项精确按 2/4 倍缩放，`yaw_rmse` 变化 0.8%，即没有变化。**

写下这条假设时预设了一个二选一：要么转向恢复（机理确认），
要么"极限是 INT8 的 yaw 分辨率本身"。**真相是第三种，而且更根本**：

> **优化器根本没有在迈步。**

W8A8 的学习率在 **2000/2000 次迭代**都被钉在 1e-5 下限
（FP32 对照 10/2000）。原因是 fake-quant 让策略输出对权重**不连续**，
PPO 的自适应学习率控制器把量化边界噪声读成了策略发散：
一次 1e-5 的权重扰动在 W8A8 下产生策略 KL **6.73e-02**，
浮点下只有 **4.06e-07**——放大 **165 737 倍**，
是控制器阈值 0.01 的 **6.7 倍**，**而这还是在学习率已经为零的情况下**。

**在优化器无法迈步的前提下，改变目标函数不可能有任何效果。**
这同时解释了为什么 4× 训练预算、修正舍入、奖励重加权**三次干预全部无效**——
它们都改变了"优化器该往哪走"，没有一次改变了"优化器能不能走"。

完整分析：`experiments/goal4/goal4_final_analysis.md`。

### 这条假设错在哪里（值得记住的部分）

假设 4 本身**推理是对的**：`tracking_lin_vel = 2.0` 确实是
`tracking_ang_vel = 1.0` 的两倍，yaw 确实是奖励上的弱轴。
错的是**把"目标函数解释得通"当成了"目标函数是原因"**。

一个能解释现象的机理，不等于产生现象的机理。
分辨这两者的唯一办法，就是这次做的事：**去改变那个变量，然后看它动不动。**

## 元教训（meta-lesson）

三次的模式完全一致：

1. 观察到一个现象。
2. 找到一个能解释它的机理，且该机理有多条独立证据支持。
3. **设计一个能分离变量的实验**（逐层消融 / 直接测裁剪率 / 换掉舍入规则）。
4. 假设被推翻或大幅收窄。

**更多的观察不会推翻一个错误的假设——只有干预会。**
每次写下"这可能是因为……"的时候，紧接着要问：
**什么实验能证伪它？** 如果答不上来，那不是解释，那是叙事。

### 第四次之后新增的一条

前三次假设都关于**网络在表达什么**（latent 容量、饱和、舍入）。
第四次关于**目标函数在要求什么**。四次都错了，
因为四次都默认了同一个前提：**训练过程本身是正常工作的。**

真正的原因在**优化器的控制回路**里，而它在训练曲线上完全看不见——
奖励 28.64 对 FP32 的 29.30，健康得毫无异样。
**只有学习率轨迹会暴露它。**

**所以：低精度 RL 训练的标准诊断项，第一条应该是"打印学习率轨迹"。**
如果学习率长时间贴在下限上，那不是"收敛了"，那是控制器失效了。
